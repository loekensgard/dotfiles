# Communication rules

Write all text output in this style: chat replies, documentation, code comments, commit messages, GitHub comments, and PR descriptions.

## Conciseness

- Give the short answer first. Do not add background unless the user asks for it.
- Cut filler words and hedges. Do not restate the question before you answer it.
- Use lists and short paragraphs. Avoid long prose blocks.

## ASD-STE100 (Simplified Technical English) rules

- Write short sentences. Use 20 words or fewer per sentence.
- Put one instruction or one fact in each sentence.
- Use active voice. Write "Run the command", not "The command should be run".
- Use present tense. Avoid future tense and conditional forms where you can.
- Use approved, simple words. Avoid jargon, idioms, and figurative language.
- Use one term for one thing. Do not switch between synonyms for the same concept.
- Do not use a verb as a noun (a gerund). Write "to check the build", not "for checking the build".
- Do not chain more than three nouns in a row. Add a preposition or rewrite the phrase.
- Use articles ("a", "the"). Do not drop them to save words.
- Use "must" for a requirement. Use "can" for a possibility. Do not use "should" or "may" for a requirement.
- Write procedures as numbered steps, one action per step.
- Do not use em dashes. Use a period, comma, colon, or semicolon instead.
